# 08 · FAQ

**没有服务器能跑吗？**
不能。客户端是纯执行端，自动回复、记忆、决策全在服务端。最小形态是"一台 Linux + 一台安卓平板（或手机）"。

**要什么硬件？**
服务端 2C4G 足够（几十台设备、几百个群）；手机一台能常开充电的 Android 7.0+ 就行。推荐 4G 内存以上机型，无障碍循环长时间运行会吃内存。

**支持企业微信的哪些版本？**
只支持 Android 版企业微信（`com.tencent.wework`），主要适配**平板端**：企微平板端与手机端可以同时在线，机器人跑在平板上，不会把本人手机上的企微挤下线。手机端也能跑，但界面结构与平板端有差异，个别定位可能不灵，需要按 09 调。iOS 版、macOS / Windows 桌面版、网页版，以及企微 3.x 及更早的 Android 版本都不支持。

**能管多个企业微信账号吗？**
能。一个账号 = 一台手机 = 一台设备。设备可以共用一套组织资源；长期记忆可以多设备共享同一套（一台写、其余只读，或多台共同维护）。

**聊天记录会被上传到 LLM 厂商吗？**
取决于你在智能体里配的模型。配 OpenAI/DeepSeek 等云端服务，消息正文会发过去；配本地 ollama（OpenAI 兼容）就完全不出内网。这件事在 07 里有单独的威胁条目，请如实告知你的客户。

**能不能用模拟器/云手机？**
技术上可以，实际不推荐：无障碍服务在模拟器上的窗口结构与真机有差异，行内已踩过的定位问题大多来自真机；云手机的触控与渲染延迟会让"进房间→发消息"这种多步操作更容易失败。

**会不会被封号？**
自动化操作有风险，本项目不做任何对抗检测的处理（不做随机化、不做频率伪装），也不承诺安全。用小号先跑、控制频率、不要群发。

**企业微信改版了怎么办？**
客户端定位集中在 `service/WeworkOperationImpl.kt` 与 `utils/WeworkRoomUtil.kt`，改版时通常只需改这几处（加上 `uiautomator/*.xml` 的界面 dump 对照）。这是本项目维护成本的来源，也是它"慢"的原因。

**模型能用哪些？**
任何 OpenAI 兼容接口：`base_url` + `model` + `api_key` 三件套。已实测过 OpenAI、DeepSeek、通义、ollama。embedding 同理。

**能不能商业化/卖给客户？**
可以。Apache-2.0 允许商用、闭源修改、SaaS 化。唯一限制是商标：别用 "SevFish / SevFishComVBot" 当你的产品名，别暗示官方背书。

**为什么不发预编译 APK？**
两个原因：一是无障碍权限极高，来源不明的 APK 会被利用；二是避免有人把原版 APK 换个壳当自己的产品卖。请自己编译（`./gradlew assembleDebug`）。

**没有前端构建，后台是原生 HTML？**
是。管理后台是服务端直出的 HTML（`app/layout.py` 提供导航与样式，`routes/*.py` 拼页面），改一个页脚不需要 `npm install`。这是刻意的取舍：少一层构建，部署只依赖 Python。

**数据怎么备份/迁移？**
MySQL + `uploads/`，见 06 第 5 节。导出整个库就能搬到新机器。

**为什么代码里注释是中文？**
项目从中文业务场景长出来，注释保留了踩坑现场的原始记录（"这里曾经把未读数当成房间名"这种）。这些注释是资产，不打算翻译掉。

**我想只实现客户端、接自己的服务端？**
可以。协议只有几页（05），最小实现三条消息：心跳、上报 101、执行 203 并回执。

**issue 多久回？**
这是一个低维护项目：bug 会修，功能请求看契合度。想推动什么，最好的方式是 PR + 一段"为什么"。
